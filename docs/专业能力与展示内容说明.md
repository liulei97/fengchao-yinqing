# 蜂巢引擎 Personal Harness｜咨询、规划与建筑专业能力展示说明

> 性质：完整产品形态展示说明。该文档**不是**开发计划、排期表或真实部署验收报告。网页中的交互与图形均使用离线概念数据，旨在说明建成后的专业工作方式。

## 一、产品统一定位

蜂巢引擎是统一的 Personal Harness，不为工程咨询、规划编制、建筑设计分别建立互不关联的 Agent 系统。其共有基础是：项目上下文、原始文件及派生文件、知识索引、证据包、任务及执行身份、专业工具、AI 模型路由、审定意见与可编辑交付成果。

完整展示页包括原有的知识检索、政策关系、WebGIS、城市设计、AI 画布、AI 生图、技术底座与成果交付，以及本次新增的三个专业工作台：**工程咨询、国土空间规划、建筑设计多专业协同**。

## 二、工程咨询与政策研究工作台

### 2.1 页面交互

展区提供四种模式，切换后同步更新**输入材料列表、分析工作步骤、文稿大纲、正文样例、证据提示与输出格式**。报告支持一键复制示例摘要。

### 2.2 四条具体工作链

| 模式 | 典型输入 | 关键分析环节 | 示意交付 |
|---|---|---|---|
| 项目策划与论证 | 项目目标、资产范围、权属、空间与历史材料 | 项目界定、事实/假设/未知分层、约束与路径辨析 | 项目策划研究、问题清单、实施建议 |
| 政策与审批研究 | 法规政策原文、文号与时点、规划及项目手续 | 效力与适用、条款—事实匹配、冲突及缺项核查 | 政策关系图、适用矩阵、审批事项流程研究 |
| 可研与实施研究 | 需求与规模、建设条件、技术方案、投资及运营假设 | 方案比较、投资与运营测算、敏感性分析、风险识别 | 可行性研究、投资测算工作底稿、风险清单 |
| 咨询文本编写 | 正式材料、报告深度与模板、计算结果、审稿意见 | 结构化大纲、段落写作、引用追溯、跨章节校核与修订 | Markdown、离线 HTML、Word、PDF、引用与修改记录 |

### 2.3 强化的咨询业务场景

**国土空间与用地政策研究。** 基于政策原文、地域、施行时点、修订谱系和项目事实，研究用途管制、三区三线、建设边界、土地供应、存量盘活、用地手续及历史遗留问题。每项判断都应区分“政策文本明确要求”“已确认的项目事实”“研究推论”“仍需核验事项”。

**建设项目前期综合咨询。** 从问题定义、选址建设条件、技术可行性、投资估算、运营和经济效益，到风险及实施管理，连接咨询报告、表格和专业分析图。金额、工程量和收益率必须来自可信表格和专业计算。

**规划实施与项目落地咨询。** 对规划符合性、项目规划许可、用地审批、土地储备和供地、详细规划调整等事项开展条件研究和流程表达。由于法律规范具有适用时点和地方差异，演示页面不预设任何真实项目一定符合某项政策。

### 2.4 长文本能力应如何理解

- 自动整理材料不是自动认定事实。
- AI 通过证据回读与约束检索协助写作，专业人员审定结论。
- 一个政策原文变化，应定位受到影响的引用、章节、图件和表格。
- 图件、数据表和报告不是互不关联的静态附件，而是同一项目的一组可编辑成果资产。

## 三、国土空间规划编制工作台

### 3.1 四类规划业务可切换

| 规划类型 | 重点研究内容 | 示意成果 |
|---|---|---|
| 村庄规划 | 村庄类型与定位、现状用地、三区三线、居民点与宅基地、产业、设施、风貌、项目库 | 规划文本、说明书、村域图、居民点图、项目库、矢量数据 |
| 总体规划研究 | 资源环境评价、空间结构、人口产业、用途管制、重大设施、指标与传导 | 总规文本、格局图、控制线图、专题研究、指标表、数据库 |
| 详细规划 | 单元和地块功能、开发强度、道路、市政、公共空间、设计指引与地块图则 | 详细规划文本、地块图则、指标表、土地利用图、设施图 |
| 专项规划 | 交通、生态、绿地、市政、公共服务等需求分析与设施布局 | 专项规划文本、设施布局、服务区图、项目库、专题数据库 |

切换规划类型后，展示中的**项目名称、地图标题、基础数据分类、文本章节、章节说明和交付成果**一起改变，而非仅更换标签。

### 3.2 国土空间规划研究过程

1. **现状资料与底图构建**：三调及年度变更数据、影像、人口产业、权属、道路、市政、生态环境、现状建设和项目清单；核对版本、坐标系、数据完整性与拓扑错误。
2. **规划约束核查**：永久基本农田、生态保护红线、城镇开发边界、上位规划约束、生态保护、风险与专项控制；将GIS相交结果与文字约束分别存证。
3. **发展定位及需求研究**：人口、产业、设施、城镇与乡村空间发展要求；从调查事实到方案目标形成可回溯判断。
4. **空间布局和方案比选**：用地调整、产业设施、住房、公共服务、交通、市政、生态修复、文化保护、形态与风貌设计。
5. **指标测算及控制**：面积和数量来自真实地理运算；统计口径、分类规则、空间参考、精度与计算回执随表保留。
6. **文本、说明书、图件、图则协同**：章节、图例、面积表、用地编码、规划图层和图框版本保持一致。
7. **检查与交付**：技术一致性、图面质量、政策适用性、专业审查及成果归档，不使用 AI 自行编造的面积或控制值。

### 3.3 图件制作的明确分工

- **ArcPy / GIS 专业引擎**：空间相交、Union、缓冲区、统计、属性处理、投影和制图数据准备。
- **ArcGIS Pro / Pro Bridge / 排版工具**：图层、符号化、标注、图例、比例尺、指北针、图框、布局及批量导出。
- **AI 研究与写作**：理解图件表达目的、整理样式规范、引用真实计算结果、组织图件说明并识别文图不一致。
- **交付与版本**：矢量数据、PDF/图片、说明书、表格与图纸的对应关系，及专业审查与修改记录。

页面的交互地图可显示或隐藏“规划意向、生态约束、耕地约束、道路、水系”五类示例图层。该地图**不含真实地理坐标，不得用其解读用地边界、面积或法定管制结论**。

## 四、建筑设计十二专业与协作方向

| 工作方向 | 内容深度 | 专业交付与审查 |
|---|---|---|
| 建筑方案 | 功能策划、场地、体量、流线、立面、功能面积 | 总平面、平立剖、方案说明、模型与面积复核 |
| 结构 | 结构体系、柱网、荷载条件、受力模型输入 | 计算书索引、结构图、冲突问题；工程师核验安全 |
| 给排水 | 给水、污废水、雨水、消防水、设备与竖井 | 系统图、专业平面、材料表、水力计算核验 |
| 暖通 | 空调、通风、冷热源、设备、机房、建筑能耗 | 暖通方案、系统图、负荷及能耗专业分析 |
| 电气 | 供配电、照明、配电间、设备和线缆路由 | 平面、系统图、设备表、电气专业校审 |
| 智能化 | 综合布线、安防、楼宇自控、弱电机房 | 弱电系统图、网络拓扑和设备点表 |
| 消防 | 建筑防火、多专业消防设施、疏散、排烟 | 消防专篇、各专业图纸与适用规范校审 |
| 景观 | 竖向、种植、水系、慢行、公共空间 | 景观总平、种植、竖向、节点和表现图 |
| 幕墙 | 表皮、材料分格、连接节点、遮阳与性能 | 幕墙方案、深化模型、节点详图和专业计算 |
| 室内 | 功能、室内流线、材料、家具、天花与照明 | 室内平面、天花、立面、材料表和效果图 |
| BIM 协同 | 全专业模型、构件身份、变更、碰撞和议题 | 模型问题清单、协调版本与交付核验 |
| 造价与工程量 | 算量口径、材料清单、概估算、成本差异 | 工程量表、成本比较和专业复核底稿 |

建筑协同页面可以在 12 个方向之间切换。建筑模型还支持独立叠加结构框架、机电管线、电气路由和景观环境。示意模型**不是 BIM 文件，也未执行真实碰撞检测或工程设计计算**。

### 4.1 多专业协同中的统一模型观

专业模型不必都在一个工具中生成。CAD、SketchUp、Rhino/Grasshopper、各专业 CAD/BIM 软件、GIS 和视觉引擎负责相应对象；Personal Harness 把设计条件、参数、版本、执行记录和修改影响联系起来。不同软件输出的数据质量由对应专业工具控制，不能由语言模型推断取代。

### 4.2 建筑设计与城市设计的连接

WebGIS 保持真实场地位置、地形与规划约束；AI 画布组织设计策略；CAD/SU/Rhino 生成二维和三维几何；专业模型研究形态、交通、环境及建筑系统；AI 生图在底图、白模、视角、参考与 Mask 约束下生成彩平、鸟瞰、街景和空间氛围候选；通过审查后进入可编辑成果包。

## 五、用户可实际操作的产品演示

- 在统一工作台侧边栏切换咨询、规划、建筑专业视图，原有七种视图仍保留。
- 咨询工作台切换四种业务，观察输入、分析、文稿及交付同步变化；可复制示例摘要。
- 规划工作台切换四种规划，选择具体文本章节，并勾选地图约束图层。
- 建筑工作台切换十二类专业，同时勾选不同模型可视叠加层。
- 原城市设计专题继续保留 WebGIS、AI 设计画布、方案视角和建筑形态等已有交互。
- 技术架构继续通过五组交互卡展示十一层底座，突出统一任务、证据与成果的关系。

## 六、设计说明与使用边界

这些新增业务界面的**组织方式、展区、交互、文字和示意图**是依据 Personal Harness 技术路线展开的产品体验设计，不代表上传的技术实施文档已逐项规定了所有咨询、规划、建筑专业细节，更不代表相应专业工具在当前环境中已实际接入。

产品页面特意不展示开发阶段、排期、完成百分比和验收台账。对于业务应用，保留最必要的概念演示声明：政策效力需要现行依据、GIS 数值需要真实计算、工程设计和审批事项需要适用标准及专业审查。
