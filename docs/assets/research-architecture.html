07 / KNOWLEDGE-GROUNDED AGENTIC RESEARCH

知识不只是被检索。
让每一步专业判断都有来处。

知识库是整个 Personal Harness 的长期证据基础。面对简单查询，走低成本混合检索；面对复杂政策研究，Agent 自主拆分问题、回读原文、追踪版本、发现反证，再组织成可复核的分析成果。数据来自哪里、是否适用、哪些结论仍待核实，始终分开表达。

RESEARCH EXECUTION / INTERACTIVE MODEL一项政策问题的三种执行深度
三种演示模式 · 同一证据基础

点击模式，观察任务分解和结果形态

KNOWLEDGE / L1

找到政策原文，再给出带出处的回答

适合文号、名称、条款定位及范围明确的事实性问答，减少不必要的多轮模型调用。

EXAMPLE / 待研究的问题

某项土地政策的第几条涉及适用条件？

    研究者做什么审核政策效力、项目事实和结论边界
    Agent 做什么组织检索与分析，不自行签署审批结论
    KNOWLEDGE / 数据权威

    一个正式 INDEX，三条取证入口

    01 / CONTROLLED正式知识索引Source → OCR/解析 → FTS5/BM25 + BGE-M3 → Rerank
    02 / TEMPORARY临时材料探索未入库文件夹 / 原件读取 / 原始来源记录
    03 / EXTERNAL公开网络检索DeepSeek Search/Fetch 与 Exa 作为可替换候选

    三路结果可以进入同一任务证据池，但不能擅自修改正式 INDEX。Wiki 负责组织已形成的知识，不能代替政策原文或专业效力判断。

    EVIDENCE / 证据晋级路径

    搜索结果不等于结论

    SearchHit网页线索和摘要
    FetchSnapshot抓取内容、时间与来源
    EvidenceItem原文定位与核验记录
    EvidencePacket冻结用于当次研究的证据
    Claim分清原文、推断、建议和待核项

    政策法律效力、地域与项目适用性由 Policy 领域按时间和事实核验；检索相关性分数不能替代这些判断。

    08 / INTELLIGENT ORCHESTRATION

    研究路径可以动态生成，
    执行权限不能随意生成。

    Agent Loop 负责探索，LangGraph / 有界 Runner 负责有状态执行；遇到天然可拆分的任务，可借鉴 ZCode 的 TypeScript Workflow 机制编排子 Agent。所有 Runner 都服从同一个 Task Core 的计划、授权、预算、执行身份与恢复规则，避免双 Agent Loop 同时驱动同一次任务。

    PARALLEL WORKFLOW / ILLUSTRATIVE DEMO同一业务任务，多 Agent 并行研究再汇总
    交互式流程模型

    切换查看子任务与交付汇总变化

    POLICY / PARALLEL STUDY

    一份研究目标，分成三个可复核专题

    Task Core 接受任务、授权与预算
    ↓
    Runner 生成受控的子任务 DAG
    ↓
    ↓
    证据合并 → 冲突分析 → 结构化报告
    TASK GOVERNANCE / 任务治理

    动态脚本是执行提案，不是另一套任务权威

    • 生成：Agent 根据本次目标提出流程和类型化输入输出。
    • 编译校验：检查结构、循环、能力、依赖、预算和副作用。
    • 授权执行：Task Core 接受计划，Runner 才能创建获准的 attempt。
    • 修订：PlanPatch 受控生效，历史计划与运行回执保留。
    • 增量复用：仅在输入、版本、身份和副作用条件允许时复用结果。
    
    
    
    
    Task Core ≠ Runner ≠ Subagent失败、取消、超时或执行结果未知时先对账；重放缓存不等于允许重复修改外部文件。
    
   
    
  
    
  
    
   
    WEB RETRIEVAL / REPLACEABLE PROVIDERS
    公网搜索是工具通道，不是第二知识底座
    DeepSeek Search / Fetch候选：网页搜索、网址定位、正文读取与研究材料获取。待真实评测
    Exa Search / Contents候选：语义发现、内容获取，与中文政策官方来源检索对照。对照评测
    SEARCH查找线索查询、URL、排名、摘要
    FETCH回读网页正文、获取时点、失败范围
    VERIFY核查入证官方来源、原文、效力与适用
    
   
    MODEL ROUTING / RESPONSIBLE COST
    把成本花在必要的研究深度上
    Hybrid RAG 复用正式 INDEX 的混合检索；必要时精排并回读原文，不自动启用多 Agent。
    成本、响应时间和检索质量需经同一组真实任务测量。展示页不伪造 DeepSeek / Exa 的召回率、时延和费用对比结果。
    
  
    
 
    

    


    
 
    
  
    09 / MULTI-PERSPECTIVE SYSTEM ATLAS
    
  
    同一套体系，
    从四种视角读懂它。
    
  
    面向客户，它是一个贯穿研究与交付的工作平台；面向架构师，它是有权威边界的控制与证据系统；面向开发者，它由稳定语义契约与可替换 Runner 构成；面向专业人员，它是一组把政策、项目、空间、设计与成果贯通的工作链。

    NODE INSPECTOR / 节点详解
    任务与需求
    从工作目标开始，统一界定输入、范围、用途和预期成果。
    每一条工作链都以可复查的来源、执行记录与成果版本为基础。

    CONTROL PLANE
    Task Core 掌握许可
    计划接受、attempt、lease、fence、取消、预算、成果接受，不因换 Runner 或桌面客户端而丢失。
    
   
    EXECUTION PLANE
    Runner 调度真实能力
    LangGraph / Agent Loop / 可选动态工作流调用模型、MCP、ArcPy 和专业软件桥，真实回执决定执行状态。
    
   
    EVIDENCE PLANE
    Source 和领域对象保存事实
    正式 INDEX 只有一个受控写入口；EvidencePacket、政策 Claim、GeoResult 和 DesignResult 各由相应责任域核验。
