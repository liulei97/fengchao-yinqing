## 1. 结论摘要

1. ChatGPT 网页端的“混搭”不是设计失误，而是**五代渲染机制并存**：Markdown、DIL 布局、基础件、学习模块、自定义 JSX、页面快照。
2. 它的核心优点是**服务端可控制 UI、分层表达、安全边界、失败隔离、跨端降级**；代价是**导出不可携带、版本漂移、多份表示、第三方难复刻**。
3. 迁移 PersonalHarness 不应复刻 ChatGPT 的组件，而应复刻它的**分层与路由**：先分类，再分流，每类留回退。
4. 迁移的第一资产不是模板，而是 `blocks.json`：把“看到的图”变成“可渲染的块”。
5. 必须保留三种策略：`native`（可交互重写）、`frames`（离散快照）、`static`（单张图）。
6. 不允许把模型生成的任意 JS/JSX 直接执行；模板只来自注册表，运行时只跑已审核代码。
7. 离线是验收项：单文件、无 CDN、断网可读。
8. 迁移顺序：分类器 → 块模型 → 注册表 → HTML 渲染 → 验收器 → 多目标。

## 2. 机制解构：ChatGPT 的六层

### 2.1 分层表

| 层 | 名称 | 典型标记 | 是否可执行 | 是否有类型 |
|---|---|---|---|---|
| L0 | Markdown 原生 | `#`、`|`、``` | 否 | 否 |
| L1 | DIL 声明式布局 | `<box>`、`<grid>`、`<row>`、`<badge>` | 部分 | 否 |
| L2 | DIL 基础件 | `<Chart>`、`<AsyncImage>`、`<slider>`、内联 `<svg>` | 部分 | 部分 |
| L3 | 学习模块 | `matched_type`、`content_references` | 是 | 是 |
| L4 | 自定义 DIL JSX | `{@body const [x,setX]}`、`DIL.useState` | 是 | 否 |
| L5 | 页面快照 | `figure.os-svg`、`os-figure` | 否 | 否 |

### 2.2 组合是任意嵌套

已实测的组合：

```text
Markdown
└─ DIL <box>
   ├─ <Chart content={…}/>
   ├─ <AsyncImage query=…/>
   ├─ 内联 <svg> + {#each}
   └─ <slider> + caption

DIL <box>
└─ __chatgptClientDefinedWidget
   └─ matched_type = DEMAND_CURVE
```

结论：不能按“顶层标签”判断类型，必须**递归识别**。

### 2.3 同一视觉的四种来源

| 来源 | 例子 | 导出难点 |
|---|---|---|
| Chart JSON | `<Chart content={{...}}/>` | 表达式/JSON 被误处理 |
| DIL 内联 SVG | `{#each}` + `<svg>` | 循环/索引表达式 |
| 自定义 JSX | `useState` + 公式 | 无法静态求值 |
| 页面快照 | `figure.os-svg` | 只有一张状态、尺寸失真 |
| 学习模块 | `matched_type` | 需要模板与版本 |

这解释了为什么“看起来一样，导出结果完全不同”。

## 3. 为什么这套机制有效

| 优点 | 机制 | 对 PH 的启示 |
|---|---|---|
| 服务端控制 UI | 下发 DSL/类型，前端渲染 | 组件升级不动客户端 |
| 分层表达 | 文本/布局/交互/图各用其器 | 不要所有内容都富文本化 |
| 安全边界 | 受限 DSL + iframe 沙箱 | 不执行任意 JS |
| 失败隔离 | 单组件失败不拖垮页面 | 每块独立回退 |
| 跨端降级 | 同一内容多渲染目标 | blocks → HTML/PDF/MD |
| 个性化 | `matched_type` + version | 注册表按版本 |
| 内容部分解耦 | 数据、类型、渲染分离 | blocks.json |

## 4. 代价

| 代价 | 表现 | 缓解 |
|---|---|---|
| 不可携带 | 导出后脱离服务端失效 | 构建期内联 |
| 版本漂移 | v1/v3/v4 行为不同 | `(source,type,version)` |
| 多份表示 | 快照 + 源码 + 元数据 | 主/从声明，去重 |
| 状态丢失 | 只保存当前页签 | frames 或 native |
| 体积膨胀 | iframe + 字体 + 运行时 | 资源子集、按需内联 |
| 第三方难复刻 | 私有 DSL/协议 | 只复刻高频类型 |

---

## 5. 迁移原则

1. **搬分层，不搬组件**：先有分类与路由，再逐个补模板。
2. **先块模型，后渲染器**：没有 `blocks.json`，模板越多越乱。
3. **类型优先，签名兜底，快照最后**。
4. **不执行未审核代码**：模板只来自注册表。
5. **每个块必须有回退**：模板 → 快照 → 表格 → 文本。
6. **离线是一等验收**：单文件、无外链、断网一致。
7. **AI 只生成候选**：人工采用后才进注册表。

## 6. 目标架构

```text
来源
  ChatGPT HTML / JSON
  Claude / Markdown / DOCX
        ↓
分类器 Classifier
  四问：type? DIL? useState? snapshot?
        ↓
blocks.json
        ↓
Registry
  (source,type,version) → native/frames/static
        ↓
renderBlock(block, target)
        ↓
HTML / PDF / Markdown / PPT
        ↓
Validator
```

### 6.1 分类器四问

```text
Q1 有 matched_type 吗？
   有 → A 类：查注册表
Q2 有 {#each}/<box>/<grid> 吗？
   有 → B 类：DIL 渲染
Q3 有 DIL.useState(...) 吗？
   有 → C 类：签名匹配，否则静态兜底
Q4 只有 figure.os-svg / os-figure 吗？
   有 → D 类：静态图
```

### 6.2 路由表

| 类别 | 判据 | 策略 | 回退 |
|---|---|---|---|
| A 类型化 | `matched_type` | native 模板 | 快照 |
| B 结构型 | DIL 标签 | DIL 渲染器 | 文本 |
| C 状态型 | `DIL.useState` | 签名模板 | 快照/隐藏 |
| D 快照型 | `os-svg` | 静态图 | caption |
| E 提示词型 | `AsyncImage` | 占位卡 | 文本 |

### 6.3 伪代码

```python
def classify(fragment):
    if has_matched_type(fragment):
        return "typed"
    if has_dil_structure(fragment):
        if has_usestate(fragment):
            return "stateful"
        return "dil"
    if has_snapshot(fragment):
        return "snapshot"
    if has_async_image(fragment):
        return "prompt"
    return "markdown"
```

```python
def route(block):
    if block.kind == "typed":
        return registry.render(block.type, block.version) or fallback(block)
    if block.kind == "dil":
        return dil_renderer.render(block.source) or fallback(block)
    if block.kind == "stateful":
        return signature_registry.render(block.source) or fallback(block)
    return static_renderer.render(block)
```

## 8. 块契约（迁移最小版）

```json
{
  "id": "blk_...",
  "source": "chatgpt",
  "kind": "typed",
  "type": "widget.DEMAND_CURVE",
  "version": 3,
  "data": {},
  "state": { "price": 5, "shift": 0 },
  "evidence": [],
  "fallback": { "kind": "snapshot", "ref": "fig_..." },
  "render": { "prefer": "native", "allow": ["native", "frames", "static"] }
}
```

最小实现只需要：

```text
id / kind / type / data / state / fallback
```

其余字段后补。

## 9. 迁移阶段

### P1｜分类器与块模型

| 项 | 内容 |
|---|---|
| 产出 | `classify()`、`blocks.schema.json`、样例 20 块 |
| 验收 | 五类都能识别；错分可人工修正 |
| 风险 | DIL 嵌套导致误判 |

### P2｜注册表

| 项 | 内容 |
|---|---|
| 产出 | 6 个既有模板入库；版本键 |
| 验收 | A 类全部命中；缺模板走回退 |
| 风险 | 版本命名 |

### P3｜HTML 渲染器

| 项 | 内容 |
|---|---|
| 产出 | `renderBlock` + 五种块 |
| 验收 | 单文件离线；截图检查 |
| 风险 | 旧脚本兼容 |

### P4｜回退与去重

| 项 | 内容 |
|---|---|
| 产出 | 模板→快照→文本；主/从声明 |
| 验收 | 无重复图、无 JSX 残留 |
| 风险 | 快照缺失 |

### P5｜验收器

| 项 | 内容 |
|---|---|
| 产出 | 外链/NaN/图表/截图/离线检查 |
| 验收 | 三份真实报告零误报 |
| 风险 | 视觉断言不稳定 |

### P6｜多目标

| 项 | 内容 |
|---|---|
| 产出 | Markdown/PDF 目标 |
| 验收 | 同块同内容 |
| 风险 | 分页/字体 |

## 10. 验收清单

- [ ] 五类块各至少一个样例；
- [ ] 每个块有 fallback；
- [ ] 无 `matched_type` 时不误判为 A；
- [ ] 有 `useState` 时不把 JSX 当文本；
- [ ] 快照 SVG 有自然尺寸与字体约束；
- [ ] 同一模块不同时出现快照与源码；
- [ ] 单文件无 `http(s)` 外链；
- [ ] 断网打开与联网一致；
- [ ] 1440/1024/390 无横向溢出。

---

## 11. 风险与边界

| 风险 | 影响 | 缓解 |
|---|---|---|
| 分类错误 | 块进错渲染器 | 人工修正 + 日志 |
| 模板爆炸 | 维护成本 | 高频 native，低频 static |
| 版本漂移 | 旧块重渲染失败 | version + fallback |
| 快照缺失 | 无法兜底 | 采集时强制保存 |
| AI 生成错误 | 数值/安全 | 人工采用 + 数值验收 |
| 体积膨胀 | 打开慢 | 资源子集 |

边界：

- 不承诺还原 ChatGPT 全部私有组件；
- 不承诺任意 DIL 自动可交互；
- 不承诺像素级一致；
- 不改变 P9/P10 顺序。
